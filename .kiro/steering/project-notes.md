## 사용 규칙

- '프로젝트 기록을 읽어줘'라고 하면 위 페이지 ID로 Notion MCP를 통해 실제로 읽는다.
- '오늘 작업을 기록해줘'라고 하면 해당 페이지를 먼저 읽고, 변경안을 보여준 뒤 확인을 받아 저장하고, 저장 후 다시 읽어 결과를 확인한다.
- 읽기나 저장에 실패하면 성공했다고 말하지 않는다.
- 다른 페이지로 바꾸거나 새 페이지를 만드는 것은 먼저 사용자에게 확인한다.
- 기존 내용(목표, 작업 위치)은 보존하고 현재 상태·결정과 이유·다음 작업만 갱신한다.
- 주소나 ID는 만들어 쓰지 않고, 위에 등록된 실제 값만 사용한다.

## 새 기록 작성 규칙

- **작업 일지**를 새로 만들면 `Kiro 작업 일지 모음`(40cc1f4b-755d-8160-b90d-f7ef9087d232) 하위에 넣는다. 제목은 `YYYY-MM-DD Kiro 작업 일지` 형식.
- **제출용 요약**을 새로 만들면 `제출 자료`(416c1f4b-755d-81af-9cee-cd43d3df506f) 하위에 넣는다. 교수님 확인용 공개 페이지이므로 이번 과제 기록만 담고, 허브 전체 내용은 넣지 않는다.
- **맥락/상세 기록** 성격의 페이지는 `상세 기록`(416c1f4b-755d-81cc-be7e-ce242a92947a) 하위에 넣는다.
- 새 페이지는 먼저 draft로 만든 뒤 move_pages로 해당 분류 아래로 옮긴다. 분류를 임의로 바꾸거나 새 분류를 만들 때는 사용자에게 먼저 확인한다.
- 제출용 요약에 피드백을 기록할 때 **평가자 실명을 쓰지 않고 '평가자 1, 2, …'로 익명화**한다. 받지 않은 피드백이나 확인하지 않은 결과는 지어내지 않는다.
- 게시(Publish to web)는 **제출용 요약 페이지 개별로만** 한다. 상위 허브·분류 페이지(유레카 프로젝트, 상세 기록, 제출 자료)와 상세 기록 하위는 비공개로 유지한다.
